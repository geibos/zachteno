# Security-ревью «Зачтено», октябрь 2026

Задача 14.3 OpenSpec-изменения `add-student-testing-platform`. Ревью шло в две волны по коду и конфигурации развёртывания: аутентификация, CSRF, права на объекты, загрузка файлов, CSV-инъекции, XSS, SQL, SSRF, секреты в логах, раскрытие аккаунтов, деплой. Каждое исправление закрыто тестом на сценарий эксплуатации.

## Первая волна (во время реализации) — исправлено

| Находка | Исправление |
|---|---|
| Перебор аккаунтов при входе: ответ и время отличались для существующего email | Одинаковый ответ и пауза, ложный хеш для несуществующего email; блокировка видна только после верного пароля |
| Гонка счётчика неудачных входов | Атомарная резервация попытки (`try_begin`) |
| Письма восстановления и подтверждения без ограничений | Лимит по IP и не чаще одного письма одного назначения в минуту |
| Unicode-омоглифы в email | Только ASCII в адресе |
| Дорогой хеш пароля считался до проверки ссылки сброса | Сначала проверка токена, потом Argon2 |
| Захват неподтверждённой учётки при выдаче роли суперпользователя через CLI | Пароль, сессии и внешние входы такой учётки сбрасываются |
| GIF- и пиксельные «бомбы», большое тело загрузки | Лимиты сторон, бюджет кадров, `max_alloc`, лимит тела, частота загрузок на пользователя |
| Открытый редирект через `next` | Белый список символов пути |
| Решения антифрода по чужим связям | Только участники курса, данные посторонних маскируются |
| CSRF через автовступление на `/invite` | Вступление только по явному действию и флагу на клиенте |
| Лишние секреты в контейнере приложения, метрики в общей сети | Явный список переменных окружения, метрики на `127.0.0.1` |

## Принятые риски

- **Регистрация на занятый email сообщает «занят».** Так требует сценарий «Занятый email» в `identity-auth`; перебор ограничен лимитом регистраций по IP.
- **F10. Пауза входа по email жертвы.** Нарастающая пауза после неудач по email — требование spec; злоумышленник может удерживать паузу до 15 минут. У кого привязан Яндекс ID, входит через него в обход паузы.
- **F15. `TRUSTED_PROXIES` по умолчанию пуст.** Безопасное значение: без него `X-Forwarded-For` не учитывается. За прокси его нужно задать, иначе все клиенты делят лимиты одного IP (описано в `deploy/compose/README.md`).
- **Сигналы антифрода присылает клиент.** Их можно подделать и создать ложную связь. Антифрод по spec только сигналит: ничего не блокирует и не меняет баллы, решение принимает проверяющий; распространённые отпечатки и `same_hardware` в транзитивные пути не входят, посредников не больше 50.
- **Решение по связи глобально для пары аккаунтов** — допущение дизайна (связь одна на пару, не на курс).
