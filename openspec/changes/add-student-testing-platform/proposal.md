# Proposal

## Why

Нужен собственный сервис тестирования студентов. Методисты в нём собирают курсы из тестов, преподаватели ведут потоки и смотрят результаты, студенты проходят тесты. Готовые LMS не устраивают по трём причинам: нет гибкого оценивания (веса, штрафы за неверные варианты), нет синхронного открытия и закрытия тестов для потока, нет прозрачного учёта приглашений и сигналов о мультиаккаунтах. Проект пустой, это первый change, и он закладывает весь MVP.

## What Changes

- Новый клиент-серверный сервис: бэкенд на Rust (axum, sqlx, PostgreSQL), фронтенд на SvelteKit со статической сборкой, которую раздаёт бэкенд. Картинки хранятся в S3-совместимом Garage (на Rust), фоновые задачи идут через PostgreSQL.
- Учётные записи: регистрация и вход по email и паролю (Argon2id, соль, перец), вход через Яндекс ID с расширяемым набором OAuth-провайдеров. Подтверждение email и сброс пароля.
- Роли «суперпользователь», «методист», «преподаватель», «студент». Один человек может совмещать роли. У суперпользователя есть раздел администрирования в веб-интерфейсе, первый суперпользователь создаётся CLI.
- Ссылки доверенной регистрации, которые выдаёт суперпользователь. Аккаунт, созданный по такой ссылке, помечается как доверенный.
- Курсы и тесты. Типы вопросов: одиночный выбор, множественный выбор, свободный ответ. Картинки можно прикреплять к вопросу и к вариантам ответа, текст поддерживает Markdown и формулы KaTeX. Настройки теста: веса, баллы и штрафы вариантов, режимы оценки множественного выбора, лимит попыток, таймер, свободная навигация, перемешивание вопросов и вариантов (с закреплением позиции), политика показа ответов, способ выбора итоговой попытки.
- Тест перестаёт редактироваться, как только на любой его вопрос получен первый ответ. Тест и курс можно клонировать, методист может посмотреть тест глазами студента. Попытка может содержать случайную выборку N вопросов из теста.
- Демонстрационные данные: курс «ПДД» с тестами «Экзамен» (20 случайных вопросов) и «Вся база», загружаются командой сида из открытого набора `etspring/pdd_russia`. В репозиторий набор не входит: лицензии у него нет.
- Потоки: назначение на курсы, многоразовые пригласительные ссылки с журналом использования, удобная регистрация по ссылке. Окно прохождения теста для потока открывается и закрывается вручную или по расписанию (МСК).
- Панель студента: доступные тесты, прохождение с автосохранением, серверным таймером и автосдачей, просмотр результатов в рамках политики показа. Закрытие окна не обрывает попытку с лимитом времени: она идёт до конца своего срока.
- Для преподавателя: таблица результатов «студент × вопрос», экспорт в CSV, статистика по вопросам, свободные ответы показываются без оценки.
- Антифрод: связывание аккаунтов одного человека даже при смене браузера и устройства. Для этого используются аппаратные признаки среды, граф устройств, поведенческие признаки и динамика набора текста. Кластеры вероятно связанных аккаунтов показываются с объяснением, какие сигналы совпали. Только сигнал, без автоблокировок и без влияния на оценку.
- Аудит-лог значимых действий, журнал событий попытки.
- Эксплуатация: развёртывание через Docker Compose за TLS-прокси, миграции, резервное копирование PostgreSQL и хранилища картинок на отдельный диск с проверкой восстановления, структурные логи и метрики.
- Почта: транзакционные письма через SMTP-сервис (Yandex Cloud Postbox), с SPF, DKIM и DMARC для домена стенда, чтобы письма не попадали в спам.

## Capabilities

### New Capabilities

- `identity-auth`: регистрация, вход по паролю и через OAuth (Яндекс ID), подтверждение email, сброс пароля, сессии, доверенная регистрация, первичный суперпользователь.
- `access-control`: роли и области их полномочий, назначение ролей, раздел суперпользователя, серверная проверка прав на каждый объект, непредсказуемые идентификаторы.
- `course-authoring`: курсы, тесты, вопросы, варианты, вложения-картинки, Markdown и KaTeX, настройки теста, блокировка редактирования, клонирование, предпросмотр.
- `scoring`: начисление баллов за вопрос и за попытку, веса, баллы вариантов и штрафы, режимы множественного выбора, выбор итоговой попытки.
- `streams-enrollment`: потоки, назначение на курсы, пригласительные ссылки и журнал их использования, вступление с регистрацией, окна прохождения (вручную и по расписанию).
- `test-taking`: панель студента, жизненный цикл попытки, таймер, навигация, предупреждение о неотвеченных вопросах, перемешивание, автосохранение, автосдача, просмотр результатов.
- `results-reporting`: таблица результатов, экспорт CSV, статистика по вопросам.
- `antifraud-signals`: сбор сигналов, связывание аккаунтов, объяснимые сигналы для преподавателя и методиста.
- `audit-log`: журнал значимых действий и событий попытки.
- `platform-operations`: развёртывание, резервное копирование и восстановление, наблюдаемость.

### Modified Capabilities

Нет: в проекте ещё нет спецификаций.

## Impact

- Новый код: Cargo workspace `backend/` (сервер, доменная логика, миграции, CLI), SvelteKit-приложение `frontend/`, `docker-compose.yml`, `justfile`.
- DNS домена стенда: A-запись, SPF, DKIM и DMARC для адреса отправителя.
- Стенд: каталог с compose-файлом, `.env` и данными; особенности конкретного прокси — в локальном `docker-compose.override.yml`, не в репозитории.
- Внешние зависимости: PostgreSQL, Garage (два экземпляра: основное хранилище и хранилище бэкапов на отдельном диске), Yandex Cloud Postbox (первые 2000 писем в месяц бесплатно), OAuth-приложение Яндекс ID, офлайн-база IP → ASN для антифрода.
- Секреты окружения: перец для паролей, ключ подписи сессий, OAuth client secret, API-ключ Postbox (SMTP), ключи Garage.

## Out of scope (backlog)

- Внешняя (offsite) копия бэкапов: в MVP бэкапы лежат на отдельном диске того же сервера.
- Анонимные тесты (п. 8 ТЗ): прохождение без авторизации по уникальной ссылке.
- Антифрод-сигналы, которые требуют правок инфраструктуры: реальный IP за VPN через WebRTC/STUN (свой STUN-сервер и проброс UDP) и TLS-отпечаток JA4 (TLS passthrough в прокси).
- Проходной балл и перевод баллов в произвольную шкалу оценок.
- Автопроверка свободных ответов: подсказки по регулярным выражениям, небольшая LLM.
- Срок жизни, лимит использований и отзыв пригласительных ссылок.
- Часовые пояса, кроме МСК.
- Обвязка 152-ФЗ: согласия, политика, уведомление РКН. Перед продуктивным запуском с реальными студентами нужна консультация юриста.
- Банк вопросов с тегами, импорт вопросов через интерфейс (GIFT/CSV), индивидуальные продления и дополнительные попытки, LTI, XLSX, уведомления, живой дашборд.
- Другие OAuth-провайдеры, кроме Яндекс ID (архитектура их допускает).
